FUNDAMENTALS OF PROCESS MANAGEMENT

Introduction to Process Management

Process management is one of the most important responsibilities of an operating system.

A computer may run several applications at the same time. For example, a user might listen to music, browse the Internet, edit a document, and download files simultaneously.

Chapter 1 · Fundamentals Of Process Management

Fundamentals Of Process Management

Although the processor may execute only a limited number of instructions at a given instant, the operating system coordinates these activities so that they appear to run together.

This is achieved through process management.

What is process management?

Process management is the operating system function responsible for creating, scheduling, executing, synchronizing, and terminating processes.

Its main responsibilities include:

●​ Creating and deleting processes. ●​ Allocating processor time. ●​ Managing process states. ●​ Coordinating communication between processes. ●​ Supporting synchronization. ●​ Handling process interruptions. ●​ Managing shared resources.

Why is it important?

Without process management, applications would compete uncontrollably for system resources. A computer could become unresponsive, applications could interfere with each other, and important tasks might not receive enough processing time.

Process management provides an organized environment for executing programs.

Understanding Processes

A process is a program that is currently being executed by the computer.

A program is a passive collection of instructions stored in a file, while a process is an active instance of those instructions.

For example, a web browser installed on a computer is a program. When the user opens it, the operating system creates one or more processes to execute its functions.

Main components of a process

1.​ Program code: Contains the instructions to be executed. 2.​ Data section: Holds global and static variables. 3.​ Heap: Provides memory for dynamically allocated information. 4.​ Stack: Stores function calls, local variables, and execution-related information. 5.​ Program counter: Identifies the next instruction to execute.

Fundamentals Of Process Management

6.​ Processor registers: Hold temporary values required during execution.

A process also has operating system information, such as its identifier, state, permissions, and allocated resources.

Processes allow operating systems to organize the execution of multiple applications.

Process States

During execution, a process moves through several states.

1. New

The process is being created. The operating system prepares the necessary resources and establishes its initial information.

2. Ready

The process is prepared to execute but is waiting for processor time.

3. Running

The process is currently executing instructions on a processor core.

4. Waiting or Blocked

The process cannot continue until a particular event occurs, such as the completion of an input/output operation.

5. Terminated

The process has completed its execution or has been stopped by the operating system.

Process state transitions

A process can move from ready to running when the scheduler selects it.

It may move from running to waiting when it requests an input/output operation. Once that operation finishes, the process returns to the ready state.

When execution is complete, the process enters the terminated state.

Understanding these states helps explain how an operating system manages applications efficiently.

Process Control Block (PCB)

The Process Control Block is a data structure maintained by the operating system to store information about a process.

Each process has associated management information that allows the operating system to monitor and control its execution.

Information contained in a PCB

Component Function

Process ID Uniquely identifies a process

Process State Indicates the current execution state

Program Counter Records the next instruction

CPU Registers Stores processor-related information

Scheduling Information Contains priority and scheduling details

Memory Information Describes allocated memory

Accounting Information Records resource usage

I/O Information Tracks assigned devices and operations

Importance of the PCB

When the processor switches from one process to another, the operating system saves the current process information and restores the information belonging to the next process.

This allows processes to pause and resume without losing their execution context.

The PCB is therefore essential to multitasking and context switching.

Process Creation and Termination

Processes are created when users launch applications, when operating systems start background services, or when existing processes create additional processes.

Process creation

A typical process creation sequence involves:

Fundamentals Of Process Management

1.​ Receiving a request to start a program. 2.​ Assigning a process identifier. 3.​ Allocating required memory and resources. 4.​ Initializing process information. 5.​ Creating the PCB. 6.​ Placing the process in the appropriate scheduling queue.

Process termination

A process may terminate because:

●​ It completes its assigned task. ●​ The user closes the application. ●​ An unrecoverable error occurs. ●​ The operating system stops it. ●​ A required resource becomes unavailable.

When termination occurs, the operating system releases the process's allocated resources and updates its management records.

Proper termination is important because abandoned resources can reduce system efficiency.

Process Hierarchies and Relationships

Some operating systems allow processes to create other processes.

This creates a parent-child relationship.

The original process is called the parent process, while the newly created process is called the child process.

For example, a terminal application may start a command interpreter, which then launches another program.

Process hierarchy concepts

●​ Parent process: Creates another process. ●​ Child process: Created by an existing process. ●​ Process tree: Represents relationships between parent and child processes. ●​ Process identifier: Distinguishes one process from another.

On Unix-like systems, process creation commonly uses mechanisms such as fork() and

exec().

Practical importance

Process hierarchies allow applications to divide work into separate execution units. They also help operating systems organize background services, shells, and system utilities.

THREADS AND MULTITHREADING

Understanding Threads

A thread is the smallest unit of execution that an operating system schedules within a process, depending on its scheduling model.

A single process may contain one thread or multiple threads.

Threads belonging to the same process usually share the process's code, data, and open resources, but each thread maintains its own execution state.

Main components of a thread

●​ Thread identifier. ●​ Program counter. ●​ Register values. ●​ Stack. ●​ Scheduling information. ●​ Execution state.

Example

Consider a video editing application.

It may use separate threads for:

●​ Displaying the user interface. ●​ Processing video frames. ●​ Loading media files. ●​ Encoding audio. ●​ Saving project changes.

Because these activities are divided into threads, the application can remain responsive while performing demanding operations.

Why distinguish them?

Choosing between processes and threads depends on the application's design, safety requirements, and performance goals.

Multithreading

Multithreading is the ability of a process to execute multiple threads.

Chapter 2 · Threads And Multithreading

Threads And Multithreading

It allows applications to divide work into smaller tasks that can progress independently.

Benefits of multithreading

Responsiveness: A program can continue responding to user actions while performing background operations.

Resource sharing: Threads within the same process can access shared data and resources.

Economy: Creating and switching between threads can be less expensive than managing separate processes, depending on the system.

Scalability: Multithreaded applications can take advantage of multiple processor cores.

Example: Online shopping application

A shopping application may use threads to handle user interaction, retrieve product information, process images, and update shopping cart information.

These tasks can progress independently, improving the user experience.

However, multithreading introduces challenges involving synchronization, shared data, and coordination.

Types of Threads

There are two major categories of threads based on how they are managed.

User-level threads

User-level threads are managed by a thread library or runtime without requiring the operating system kernel to manage every thread individually.

Advantages include:

●​ Fast thread management in suitable implementations. ●​ Flexible scheduling by the application runtime. ●​ Reduced need for certain kernel operations.

Limitations depend on the implementation. In some many-to-one models, a blocking system call can prevent other user threads from running.

Kernel-level threads

Kernel-level threads are managed directly by the operating system.

Chapter 2 · Threads And Multithreading

Threads And Multithreading

Advantages include:

●​ The operating system can schedule threads independently. ●​ Multiple threads can execute simultaneously on different processor cores. ●​ Blocking one thread does not necessarily block all others.

Kernel-level management may involve additional overhead.

Modern systems commonly use kernel-supported threading.

Thread Models

Thread models describe the relationship between user-level threads and kernel-level threads.

Many-to-One

Multiple user threads are mapped to one kernel thread.

This model is simple but does not provide true parallel execution of those user threads across multiple cores.

One-to-One

Each user thread is mapped to a separate kernel thread.

This model supports parallel execution but can involve greater resource overhead.

Many-to-Many

Multiple user threads are mapped across a smaller or equal number of kernel threads.

This arrangement offers flexibility in managing execution resources.

Thread models influence performance, scalability, and the way applications use processor resources.

Thread Synchronization

Synchronization is the coordination of multiple threads or processes that access shared resources.

It prevents inconsistent results when multiple execution units attempt to modify the same information.

Why synchronization is necessary

Suppose two threads update the same bank account balance.

The original balance is ₱5,000. Both threads read the value before either writes an updated balance.

One thread withdraws ₱500, while another deposits ₱1,000.

Without proper coordination, one update may overwrite the other.

The final result could become incorrect.

Common synchronization tools

●​ Mutex locks. ●​ Semaphores. ●​ Monitors. ●​ Condition variables. ●​ Atomic operations.

These mechanisms control access to shared resources and help maintain correct program behavior.

Interprocess Communication (IPC)

Interprocess Communication refers to methods that allow separate processes to exchange information and coordinate activities.

Processes generally operate in separate address spaces, so they need communication mechanisms to share information.

Common IPC methods

Shared memory: Multiple processes access a designated memory region.

Message passing: Processes exchange information through messages.

Pipes: Provide a communication channel between processes.

Sockets: Allow processes to communicate locally or across a network.

Signals: Notify a process that a particular event has occurred.

PROCESS SCHEDULING

Introduction to Process Scheduling

Process scheduling is the operating system activity of selecting which ready process or thread should receive processor time.

Because multiple programs may request processor resources simultaneously, the operating system needs a scheduling mechanism to determine execution order.

Main objectives

●​ Maximize processor utilization. ●​ Increase the number of completed tasks. ●​ Minimize waiting time. ●​ Reduce response time. ●​ Provide fairness. ●​ Support system responsiveness.

Types of schedulers

Long-term scheduler: Determines which processes are admitted into the system for execution.

Short-term scheduler: Selects a process from the ready queue to execute on the CPU.

Medium-term scheduler: Temporarily removes processes from memory and later restores them, when supported by the operating system.

The short-term scheduler is particularly important because it makes frequent decisions about processor allocation.

Scheduling Queues

A scheduling queue is a collection of processes or threads waiting for a particular system resource or event.

Types of scheduling queues

Chapter 3 · Process Scheduling

Process Scheduling

Job queue: Contains processes that have entered the system.

Ready queue: Contains processes prepared to use the processor.

Waiting queue: Contains processes waiting for an event or resource.

How queues operate

When a process is created, it may enter a job queue. Once admitted into memory, it can join the ready queue.

The CPU scheduler selects one of the ready processes for execution.

If the selected process requests input/output, it moves to a waiting queue. After the operation finishes, it returns to the ready queue.

This continuous movement allows the operating system to manage competing activities.

CPU Scheduling Criteria

Scheduling algorithms are evaluated using several performance measurements.

1. CPU utilization

The percentage of time the processor is actively performing work.

Higher utilization generally indicates effective resource use, although maximum utilization is not always the only goal.

2. Throughput

The number of processes completed during a particular period.

3. Turnaround time

The total time between process arrival and completion.

Turnaround Time=Completion Time−Arrival TimeTurnaround\ Time = Completion\ Time - Arrival\ Time

4. Waiting time

The total time a process spends waiting in the ready queue.

5. Response time

The time between a process's arrival and its first allocation of processor time.

Why these measurements matter

An interactive computer system should provide quick responses. A batch-processing system may place greater emphasis on throughput and overall completion time.

Scheduling decisions depend on the purpose of the operating system.

Starvation

Starvation happens when a process waits indefinitely because other processes continually receive higher priority.

Aging

Aging is a technique that gradually increases the priority of waiting processes.

It helps prevent indefinite postponement and promotes fairness.

Round Robin Scheduling

Round Robin is a preemptive scheduling algorithm commonly associated with time-sharing systems.

Each process receives a fixed amount of processor time called a time quantum.

If the process does not finish within its allocated quantum, it is interrupted and returned to the end of the ready queue.

Multilevel Queue Scheduling

Multilevel Queue Scheduling divides the ready queue into separate queues according to process categories.

Each queue may use a different scheduling algorithm.

Example queue categories

●​ System processes. ●​ Interactive processes. ●​ Interactive editing applications. ●​ Batch-processing tasks. ●​ Background services.

The operating system may assign different priorities to these queues.

For example, interactive processes may receive preference because users expect fast responses.

Batch processes may receive processor time when interactive workloads are less demanding.

●​ Processes are assigned to a particular queue. ●​ Different queues may use different scheduling methods. ●​ Scheduling can occur between queues through fixed priority or time allocation.

A lower-priority queue may experience starvation if higher-priority queues continuously receive processor time.

Multilevel Feedback Queue Scheduling

Multilevel Feedback Queue Scheduling is a more flexible scheduling approach.

Unlike ordinary multilevel queue scheduling, processes can move between queues based on their execution behavior and scheduling rules.

How it works

A process may initially enter a high-priority queue.

If it repeatedly uses its entire time quantum, the scheduler may move it to a lower-priority queue.

Processes that wait too long may receive priority boosts.

Context Switching

Context switching is the process of saving the execution state of one process or thread and restoring the state of another.

The operating system performs context switching when the processor changes from one execution context to another.

Basic steps

1.​ An interrupt or scheduling event occurs. 2.​ The current execution state is saved. 3.​ The scheduler chooses another process or thread. 4.​ The selected execution state is restored. 5.​ The processor resumes execution.

Why context switching matters

It allows multiple applications to share processor resources.

However, context switching also creates overhead because time is spent saving and restoring execution information instead of performing application work.

Excessive switching may reduce overall system efficiency.

The operating system must balance responsiveness with the cost of switching between tasks.

Concurrency and Race Conditions

Concurrency occurs when multiple processes or threads make progress during overlapping periods.

On a single processor, tasks may take turns executing. On a multicore processor, some tasks may execute simultaneously.

Race condition

A race condition occurs when the result of an operation depends on the timing or order of concurrent execution.

For example, two threads may attempt to update the same inventory quantity at the same time.

Critical section

A critical section is a part of a program that accesses shared resources and must be protected against unsafe simultaneous access.

Prevention techniques

●​ Mutual exclusion. ●​ Locks and mutexes. ●​ Semaphores. ●​ Atomic instructions. ●​ Proper synchronization design.

Correct concurrency management is important in databases, banking systems, online applications, and other software that handles shared information.

Deadlocks and Resource Management

A deadlock is a situation in which two or more processes wait indefinitely for resources held by one another.

Four necessary conditions

1.​ Mutual exclusion: At least one resource cannot be shared simultaneously. 2.​ Hold and wait: A process holds one resource while waiting for another. 3.​ No preemption: Resources cannot be forcibly taken away under the relevant conditions. 4.​ Circular wait: Processes form a circular chain of resource dependencies.

Example

Process A holds Resource 1 and waits for Resource 2.

Process B holds Resource 2 and waits for Resource 1.

Neither can continue until the other releases its resource.

Deadlock handling strategies

●​ Prevention: Design the system so at least one necessary condition cannot occur. ●​ Avoidance: Grant resource requests only when the system remains in a safe state. ●​ Detection: Identify deadlocks after they occur. ●​ Recovery: Terminate processes or reclaim resources to restore progress.

Scheduling in Modern Operating Systems

Modern operating systems use sophisticated scheduling mechanisms that consider processor topology, task priority, system responsiveness, and power consumption.

Windows

Windows uses a priority-based, preemptive scheduling approach. It manages threads and assigns processor time according to scheduling priorities and system conditions.

Linux

Linux uses the Completely Fair Scheduler (CFS) for many ordinary scheduling workloads in traditional configurations. Newer Linux versions also include the EEVDF scheduling approach for fair scheduling.

macOS

macOS uses priority-based scheduling and system policies designed to support responsiveness, energy efficiency, and different application workloads.

Mobile operating systems

Mobile platforms consider battery consumption, application activity, background execution, and responsiveness.

Modern scheduling challenges

●​ Multicore processor coordination. ●​ Energy-efficient execution. ●​ Real-time deadlines. ●​ Interactive application performance. ●​ Background task management. ●​ Processor and memory locality.

Modern scheduling is not simply about selecting the shortest process. It involves balancing many system-wide goals.
