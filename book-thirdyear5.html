CHAPTER 1

Foundations of Responsive Web Design

Chapter focus: what responsive design solves, viewport and device-independent pixels,

content-first planning, fixed, fluid, and adaptive layouts, progressive enhancement and

accessibility.

1.1 What responsive design solves

Core concept

A responsive website changes its layout and presentation according to available space rather

than assuming that every visitor has the same screen. The aim is to keep information readable,

navigation usable, and controls accessible across narrow phones, tablets, laptops, and large

monitors.

How it works in practice

Start with the content and its reading order. A page should remain understandable when all

columns become a single column. Avoid designing only for a few named devices because

browser windows, zoom levels, and user preferences vary.

Implementation guidance

The three classic foundations are flexible layouts, flexible media, and CSS media queries.

Modern CSS adds intrinsic sizing, Flexbox, Grid, and container queries. Together these tools let

the design adapt without requiring a separate website for each device.

Practical code example

  <meta name="viewport" content="width=device-width, initial-scale=1">

Try it: Place the example in a simple HTML/CSS project, resize the browser, and observe how the

component behaves. Compare a narrow and a wide viewport, then check whether text, controls,

and images remain usable.

Design note: Keep the original HTML meaningful, and use CSS to adapt its presentation. The most reliable

responsive layouts preserve content access even when the visual arrangement changes.

1.2 Viewport and device-independent pixels

Core concept

The viewport is the area available for rendering a webpage. On mobile browsers the viewport

meta element helps the page use the device width rather than a wide virtual layout. CSS pixels

are not identical to physical screen pixels; they are a layout unit influenced by device pixel ratio

and zoom.

How it works in practice

A layout may be narrow because a desktop browser window was resized, not because the visitor

uses a phone. Therefore responsive rules should react to available width and content needs

instead of attempting to identify a device model.

Implementation guidance

Test at multiple widths and with browser zoom increased. If a fixed header covers text or a

dialog extends beyond the viewport, the design is not robust even if it looks good in a

screenshot.

Practical code example

  <meta name="viewport" content="width=device-width, initial-scale=1">

component behaves. Compare a narrow and a wide viewport, then check whether text, controls,

1.3 Content-first planning

Core concept

Before writing media queries, identify the essential content, primary actions, and relationships

between elements. Place important content early in the HTML and use semantic elements so

screen readers and keyboard users can understand the page.

How it works in practice

A course website might prioritize its lesson title, chapter navigation, reading text, and next-page

button. Decorative banners and secondary panels should not force the core lesson into a

cramped column.

Implementation guidance

Draw a simple narrow-screen wireframe first, then progressively enhance it for wider layouts.

This approach reduces the temptation to hide important information on phones.

Practical code example

  <main class="reading-layout">
    <article>Lesson content</article>
    <aside>Related links</aside>
  </main>

1.4 Fixed, fluid, and adaptive layouts

Core concept

A fixed-width layout assigns specific dimensions such as 1000px to a wrapper. It can overflow on

smaller screens. A fluid layout uses flexible widths so components can grow or shrink with

available space. An adaptive layout switches between selected arrangements at breakpoints.

How it works in practice

Responsive design often combines fluid sizing with intentional layout changes. A content

container can grow up to a comfortable reading width, while a sidebar can move below the

article when space is limited.

Implementation guidance

Avoid setting every width to a percentage without considering readable line length. Use

max-width for articles and minmax() for grids to preserve useful constraints.

Practical code example

  .container {
    width: min(92%, 72rem);
    margin-inline: auto;
  }

component behaves. Compare a narrow and a wide viewport, then check whether text, controls,

1.5 Progressive enhancement and accessibility

Core concept

Progressive enhancement begins with meaningful HTML that works before advanced styling or

JavaScript loads. CSS then improves the presentation and JavaScript adds optional interactions.

This strategy helps on slow networks and less capable devices.

How it works in practice

Responsive design includes more than screen width: text enlargement, touch targets, keyboard

navigation, reduced motion, and high contrast can affect usability. A menu that looks compact

but cannot be opened with a keyboard is not a successful responsive menu.

Implementation guidance

Check heading order, form labels, focus visibility, and link names. Avoid disabling zoom and do

not remove content merely because the screen is small.

Practical code example

  @media (prefers-reduced-motion: reduce) {
    * { scroll-behavior: auto; }
  }

component behaves. Compare a narrow and a wide viewport, then check whether text, controls,

Chapter focus: the css box model, relative and absolute units, fluid containers and readable

2.1 The CSS box model

Core concept

Each element is laid out as content, padding, border, and margin. Width calculations can

become surprising when padding and borders are added to a declared width. The border-box

sizing model includes padding and border within the declared width, which makes flexible

components easier to reason about.

How it works in practice

For example, a card with width: 100% and padding may overflow if it uses the default

content-box model. Setting box-sizing: border-box prevents this common problem.

Implementation guidance

Apply a global border-box reset, then use spacing thoughtfully. Margins create separation

outside an element; padding creates space inside it.

Practical code example

  *, *::before, *::after {
    box-sizing: border-box;
  }

component behaves. Compare a narrow and a wide viewport, then check whether text, controls,

2.2 Relative and absolute units

Core concept

Pixels are useful for borders and small details, but relative units often work better for responsive

layouts. Percentages are relative to a containing dimension. rem is relative to the root font size,

and em is relative to the relevant computed font size. Viewport units use the size of the

viewport.

How it works in practice

Modern dynamic viewport units such as dvh help account for mobile browser interface changes.

However, not every dimension should be tied directly to viewport height. Content should usually

be allowed to grow naturally.

Implementation guidance

Choose units based on what should control the size: font size, parent container, or viewport.

Combining units with min(), max(), and clamp() produces useful constraints.

Practical code example

  .hero {
    padding: clamp(1rem, 4vw, 4rem);
  }

2.3 Fluid containers and readable measure

Core concept

A fluid container expands within limits. The max-width property stops a paragraph from

becoming excessively wide on large screens, where long lines are difficult to scan. Horizontal

padding prevents text from touching the edge of a phone.

How it works in practice

The ch unit is based on the width of the zero glyph and can approximate a comfortable reading

measure. A line length around 60–75 characters is a useful starting point, not a universal

requirement.

Implementation guidance

Use a centered wrapper for major sections and a narrower measure for body text. This

separation helps pages remain readable across screen sizes.

Practical code example

  .article {
    width: min(100% - 2rem, 68ch);
    margin-inline: auto;
  }

2.4 Intrinsic sizing and overflow

Core concept

Intrinsic sizing allows content to influence layout. Images have intrinsic dimensions, and long

words or code snippets can create overflow if the layout has no safeguards. A flex or grid child

may need min-width: 0 to shrink below its content-based minimum.

How it works in practice

Use overflow-wrap for long addresses, and allow code samples to scroll horizontally when

wrapping would destroy their meaning. Avoid applying overflow: hidden indiscriminately

because it may clip important content or focus indicators.

Implementation guidance

Inspect pages at narrow widths with unusually long titles, URLs, and translated text. Responsive

design should handle real content, not only short placeholder text.

Practical code example

  .card { min-width: 0; }
  .article { overflow-wrap: anywhere; }
  pre { overflow-x: auto; }

Try it: Place the example in a simple HTML/CSS project, resize the browser, and observe how the

component behaves. Compare a narrow and a wide viewport, then check whether text, controls,

and images remain usable.

2.5 Modern CSS functions

Core concept

The min(), max(), and clamp() functions express flexible sizing limits without many breakpoints.

clamp() takes a minimum, a preferred value, and a maximum. It is particularly useful for fluid

typography and section spacing.

How it works in practice

For example, clamp(1.2rem, 2vw, 2rem) grows as the viewport grows but never falls below

1.2rem or exceeds 2rem. This gives designers more control than a purely fixed or purely

viewport-based value.

Implementation guidance

Use these functions where smooth changes are desirable, and media queries when the layout

needs a structural change such as moving from one column to two.

Practical code example

  h1 {
    font-size: clamp(1.8rem, 4vw, 3.5rem);
  }

component behaves. Compare a narrow and a wide viewport, then check whether text, controls,

Media Queries and Breakpoints

Chapter focus: media query fundamentals, content-driven breakpoints, combining conditions,

3.1 Media query fundamentals

Core concept

A media query applies CSS rules only when specified conditions are true. Common features

include width, orientation, hover, pointer, and user preferences. Queries should support

content-driven layout changes rather than assuming a particular phone or tablet model.

How it works in practice

A mobile-first stylesheet begins with simple default styles and adds enhancements when more

space is available. The min-width query is common in this approach. Desktop-first styles can

also work, but may require more overrides for narrow screens.

Implementation guidance

Choose a breakpoint where the content begins to feel crowded. Resize the browser slowly and

observe when cards, navigation, or sidebars stop fitting comfortably.

Practical code example

  @media (min-width: 48rem) {
    .layout { grid-template-columns: 2fr 1fr; }
  }

3.2 Content-driven breakpoints

Core concept

Popular breakpoint values can be useful starting points, but there is no universal set of phone,

tablet, and desktop widths. Devices vary, and browser zoom changes the effective CSS viewport

width.

How it works in practice

A three-card row might fit at 1000px but become cramped at 820px. The breakpoint should

reflect the card content and minimum useful card width, not the name of a device.

Implementation guidance

Where possible, auto-fitting CSS Grid can remove the need for explicit breakpoints. Use a media

query when the design requires a deliberate change in placement or interaction.

Practical code example

  .cards {
    display: grid;
    grid-template-columns: repeat(auto-fit, minmax(min(100%, 16rem), 1fr));
    gap: 1rem;
  }

component behaves. Compare a narrow and a wide viewport, then check whether text, controls,

3.3 Combining conditions

Core concept

Media queries can combine features with logical operators. For example, a layout can change

based on both viewport width and whether a device supports hover. Pointer queries can help

tailor interactions, but they should not be used to exclude keyboard users.

How it works in practice

An interface may be used with a touchscreen laptop, external mouse, or keyboard. Design

controls that work for multiple input methods instead of assuming every small screen uses

touch and every large screen uses a mouse.

Implementation guidance

Always provide a click or keyboard path for menus; hover-only navigation is fragile. Test with

real interactions, not just static screenshots.

Practical code example

  @media (hover: hover) and (pointer: fine) {
    .menu-item:hover { text-decoration: underline; }
  }

component behaves. Compare a narrow and a wide viewport, then check whether text, controls,

3.4 Container queries

Core concept

Container queries let a component respond to the size of its containing element rather than the

entire viewport. This is useful when the same card appears in a wide main column and a narrow

sidebar.

How it works in practice

Declare a query container with container-type: inline-size, then style descendants using

@container. The component can switch its internal arrangement based on the space it actually

receives.

Implementation guidance

Container queries complement media queries. Use media queries for page-wide conditions and

container queries for reusable components.

Practical code example

  .card-wrap { container-type: inline-size; }
  @container (min-width: 32rem) {
    .card { display: grid; grid-template-columns: 10rem 1fr; }
  }

Try it: Place the example in a simple HTML/CSS project, resize the browser, and observe how the

component behaves. Compare a narrow and a wide viewport, then check whether text, controls,

and images remain usable.

3.5 Testing breakpoints

Core concept

A breakpoint is not complete until the layout has been tested immediately below, at, and above

its threshold. Check whether content jumps unexpectedly, navigation overlaps, or fixed

elements hide buttons.

How it works in practice

Test browser zoom at 200%, landscape phone orientation, long text, and reduced motion.

Automated responsive previews are useful, but manual keyboard and touch testing catches

interaction problems.

Implementation guidance

Record each issue with the width and interaction that reproduces it. Fix the underlying

component constraints before adding another breakpoint.

Practical code example

  /* Test at 47.9rem, 48rem, and 48.1rem */

Flexbox and Grid for Responsive Pages

Chapter focus: flexbox fundamentals, flex grow, shrink, and basis, grid fundamentals, auto-fit

4.1 Flexbox fundamentals

Core concept

Flexbox arranges items along a main axis and manages space distribution within a row or

column. It works well for navigation bars, toolbars, button groups, and small component layouts.

How it works in practice

Use display: flex to create a flex container. The gap property adds consistent spacing, while

flex-wrap allows items to move to another line when there is insufficient room.

Implementation guidance

Avoid forcing every item into one row. If controls must remain usable on narrow screens, allow

wrapping or change flex-direction at a breakpoint.

Practical code example

  .toolbar {
    display: flex;
    flex-wrap: wrap;
    align-items: center;
    gap: .75rem;
  }

4.2 Flex grow, shrink, and basis

Core concept

The flex property controls how an item grows and shrinks and what initial basis it uses. flex: 1 1

15rem is a common pattern for cards that should fill available space but wrap when too narrow.

How it works in practice

The basis value is not a guaranteed minimum width. Apply min-width constraints when needed,

and remember that content-based minimums may prevent shrinking until min-width: 0 is used.

Implementation guidance

A flexible card row is helpful when the number of cards varies. Test with different title lengths

and images to ensure the alignment remains readable.

Practical code example

  .features > article {
    flex: 1 1 15rem;
    min-width: 0;
  }

4.3 Grid fundamentals

Core concept

CSS Grid defines rows and columns and places elements in two dimensions. It is suited to page

shells, galleries, dashboards, and complex card layouts. The fr unit distributes available free

space among tracks.

How it works in practice

Use grid-template-columns to declare columns and gap to control spacing. A common pattern

uses minmax(0, 1fr) to prevent a flexible column from overflowing because of its content.

Implementation guidance

Grid can describe a two-column page on wide screens and a single-column page on narrow

screens without changing the HTML order.

Practical code example

  .page {
    display: grid;
    grid-template-columns: minmax(0, 2fr) minmax(0, 1fr);
    gap: 1.5rem;
  }

component behaves. Compare a narrow and a wide viewport, then check whether text, controls,

4.4 Auto-fit and minmax

Core concept

The repeat() function can create repeated columns. Combining auto-fit with minmax() allows a

grid to choose how many columns fit based on available space.

How it works in practice

For a gallery, minmax(min(100%, 14rem), 1fr) prevents a card from demanding more width than

its container on very small screens. This is a flexible alternative to many explicit breakpoint

rules.

Implementation guidance

Use auto-fit when empty tracks should collapse; auto-fill can retain empty track positions.

Compare the behavior when only one or two items are present.

Practical code example

  .gallery {
    display: grid;
    grid-template-columns: repeat(auto-fit, minmax(min(100%, 14rem), 1fr));
    gap: 1rem;
  }

component behaves. Compare a narrow and a wide viewport, then check whether text, controls,

4.5 Choosing Flexbox or Grid

Core concept

Flexbox is strongest when the main concern is one-dimensional alignment and distributing

space among items. Grid is strongest when rows and columns need coordinated placement.

Many responsive websites use both.

How it works in practice

A header can use Flexbox to align a logo and navigation controls, while the main page uses Grid

for an article and sidebar. A card may itself use Grid to position an image beside its description.

Implementation guidance

Choose the layout model based on the relationships between items, not because one technique

is newer. Keep the document order logical even when visual placement changes.

Practical code example

  .site-header { display: flex; justify-content: space-between; }
  .content { display: grid; gap: 1rem; }

5.1 Flexible images

Core concept

A responsive image should fit within its container without distorting its aspect ratio. The

common rule max-width: 100%; height: auto allows an image to shrink when necessary.

How it works in practice

Images can still be too large to download even if CSS displays them at a small size. Choose

suitable source dimensions and compression to improve performance.

Implementation guidance

For an image that must fill a fixed-size card, object-fit: cover can crop it. For diagrams where

every label matters, object-fit: contain is usually more appropriate.

Practical code example

  img {
    max-width: 100%;
    height: auto;
  }

5.2 Responsive image sources

Core concept

The srcset and sizes attributes help browsers choose an appropriately sized image resource.

The picture element can offer different crops or formats for different conditions.

How it works in practice

A small phone should not need to download a huge desktop hero image if a suitable smaller

resource is available. However, image selection also depends on display density and browser

decisions.

Implementation guidance

Use meaningful alt text for informative images and empty alt text for purely decorative images.

Diagrams often need captions and surrounding explanation as well.

Practical code example

  <img src="photo-800.jpg"
    srcset="photo-400.jpg 400w, photo-800.jpg 800w"
    sizes="(max-width: 40rem) 100vw, 40rem"
    alt="Student reading a digital lesson">

5.3 Background images

Core concept

Background images are useful for decoration but should not contain essential text that could be

cropped. background-size: cover fills the available area while potentially cropping the image;

contain shows the entire image but may leave empty space.

How it works in practice

Use a background color behind the image so text remains readable if the image does not load. If

the subject of the image matters, use an img element instead of a decorative CSS background.

Implementation guidance

Check focal points at narrow and wide sizes. background-position can keep the important part of

an image visible when cropping occurs.

Practical code example

  .hero {
    background: #17375c url("hero.jpg") center / cover no-repeat;

5.4 Fluid typography

Core concept

Responsive typography balances line length, font size, line height, and spacing. Text must

remain legible when users zoom or enlarge fonts. A very small font may fit more words but

makes the page harder to read.

How it works in practice

Use rem for scalable font sizes and clamp() for headings that grow gradually. Body text often

works best at a stable comfortable size rather than shrinking with viewport width.

Implementation guidance

Test headings with long words and localized content. Use overflow-wrap carefully and avoid

clipping text with fixed-height containers.

Practical code example

  h1 { font-size: clamp(1.9rem, 4vw, 3.2rem); }
  p { line-height: 1.65; }

Core concept

7.3 Accessibility and user preferences

Core concept

Responsive interfaces should respect reduced-motion preferences, readable contrast, and text
